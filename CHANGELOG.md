# Changelog

All notable changes to `winfit` are documented here. The GitHub Release
notes are generated by GoReleaser from the commits since the previous tag;
this file is the human-facing summary.

## [1.1.0] - 2026-11-21
### Added
- `winfit get` prints a target window's position and size without moving
  it, using the same selectors as a move (`--title` / `--app` / `--hwnd` /
  `--topmost`). The `pos` / `size` / `from` numbers are logical px measured
  from the work-area edges — exactly what `--left/--top/--right/--bottom/
  --width/--height` take — so a measured window can be restored verbatim.
- `winfit get --json` emits one machine-readable object (`hwnd`, `pid`,
  `app`, `class`, `title`, `rect` and `workArea` in physical px,
  `position`/`size`/`from` in flag-ready logical px, `percent`,
  `monitor`, `scale`, `minimized`, `maximized`) for piping into `jq`.
- State notes for minimized and maximized targets, including a window that
  still carries `WS_MAXIMIZE` after a resize.

## [1.0.0] - 2026-11-19
### Added
- Initial release: position and resize Windows 10/11 windows by title,
  application name, or exact handle (or the CLI's own console), with px and
  `%` values, derived sizes, `--keep-aspect`, monitor targeting, full
  containment on resize, DPI awareness, and a selection list for ambiguous
  matches.
- `winfit list` for discovering `HWND PID APP CLASS TITLE`.
- Prebuilt `windows_amd64` / `windows_arm64` zips published by GoReleaser
  on `v*` tags.
